# plus-mail

[English](README.md) · **Русский**

Даёт каждому посетителю свой адрес почты, не меняя ваш ящик.

**979 байт min+gzip** (1 597 байт minified ESM). Без зависимостей в рантайме. ESM, CommonJS и типы TypeScript.

```js
import { plusMail } from 'plus-mail';
const { id, stop } = plusMail(['sales@example.com']);
// sales@example.com становится sales+<id>@example.com в тексте и в ссылках mailto.
```

Вызывайте после того, как доступен DOM. Случайный 16-значный hex-ID создаётся через Web Crypto и хранится локально. Тот же браузер сохраняет тот же ID между страницами. Если localStorage заблокирован, ID живёт только в этом экземпляре модуля. Некорректные сохранённые ID заменяются. При SSR возвращает `{ id: null, stop() {} }`.

Переписывает заданные базовые адреса без учёта регистра в текстовых узлах и в получателях mailto, включая несколько получателей. Query-строки mailto, разметка и обработчики событий остаются нетронутыми. Работает с динамическим контентом; пропускает код, элементы форм, редактируемый контент и уже помеченные адреса. Вызовите `stop()`, чтобы отключить наблюдатель. Базовые адреса не должны уже содержать плюс-метку.

| Опция | По умолчанию | Поведение |
| --- | --- | --- |
| `storageKey` | `'plus-mail'` | ключ localStorage для ID браузера. |
| `root` | `document.body` | элемент, чей текст и ссылки mailto персонализируются. |

Список адресов — первый аргумент. Возвращаемый `id` — созданный или сохранённый ID; `stop()` прекращает наблюдение, не отменяя уже сделанных замен.

## Чего не делает

Не отправляет и не принимает почту, не создаёт ящики, не идентифицирует человека между устройствами, не управляет согласием и не отправляет аналитику. Ваш почтовый провайдер должен поддерживать плюс-адресацию. Не меняет адреса внутри HTML-атрибутов, кроме получателей mailto, а также внутри shadow root и iframe. Очистка хранилища сайта сбрасывает ID при следующей загрузке страницы.
